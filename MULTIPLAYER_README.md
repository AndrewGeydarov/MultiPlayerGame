# Party Mini-Games — версия с сетевым мультиплеером

Учебный мультиплеер на двух устройствах для игр **Крокодил** и **Башня** на Unity 6 + Netcode for GameObjects (NGO) + Unity Transport (UTP).

---

## Что изменено по сравнению с оригинальным репозиторием

### 1. Мини-игра "Крокодил": исправлено переключение хода

**Проблема в оригинале:** ход не переходил от одного игрока к другому. Игрок мог нажимать зубы бесконечно.

**Причина:** клик по зубу обрабатывался **дважды** на каждый клик мышью:
- сначала через `Tooth.OnMouseDown()` (нормальный путь);
- затем через `CrocodileGame.Update()`, который **повторно** опрашивал мышь через `Physics2D.OverlapPoint` и вызывал тот же обработчик.

Двойной вызов → `_safeTeethPressed++` срабатывал два раза → `_currentPlayerIndex = 1 - _currentPlayerIndex` тоже два раза → текущий игрок оставался прежним.

**Исправление:**
- Из `CrocodileGame.Update()` удалён повторный опрос мыши (он намеренно оставлен пустым с комментарием).
- В `OnToothClicked` добавлена защита `if (tooth.IsPressed) return;`.
- В сетевой версии (`NetworkCrocodileGame`) клик идёт только через `Tooth.OnMouseDown → ServerRpc`, без полинга в `Update`.

После клика по «здоровому» зубу ход всегда переходит другому игроку. После клика по «больному» зубу раунд заканчивается: нажавший — проиграл, второй — выиграл.

### 2. Мини-игра "Башня": убран «Промах», только победа по числу блоков

**Изменения согласно требованию:**
- Сообщение **«Промах!»** удалено из обеих версий (`TowerGame` локальная и `NetworkTowerGame` сетевая).
- Раунд **не завершается** при промахе. Игрок просто перестаёт ставить блоки, но раунд продолжается до окончания таймера.
- Победителя определяет только **число поставленных блоков**: больше блоков → победа, равно → **ничья**.
- Проигрыша как такового нет.

### 3. ГЛАВНОЕ: онлайн-мультиплеер на двух устройствах

Добавлен полноценный сетевой режим:
- **Технология:** Unity Netcode for GameObjects (NGO) 2.1.1 + Unity Transport (UTP) 2.4.0.
- **Архитектура:** Host + Client (peer-to-peer без выделенного сервера). Один из игроков нажимает «Создать игру (Host)» и становится сервером + игроком; второй на другом устройстве нажимает «Подключиться (Join)» с IP-адресом хоста.
- **Server-authoritative:** все ключевые игровые решения (плохой зуб, чей ход, таймер) принимает сервер. Это исключает рассинхрон.
- **Сеть локальная.** Никакого выделенного сервера или облака не требуется. Достаточно, чтобы оба ноутбука были в одной Wi-Fi/LAN.

│  │ NetworkBootstrap         │  │  7777   │  │ NetworkBootstrap         │  │
│  │  ├ NetworkManager (NGO)  │  │         │  │  ├ NetworkManager (NGO)  │  │
│  │  └ UnityTransport (UTP)  │  │         │  │  └ UnityTransport (UTP)  │  │
│  └──────────────────────────┘  │         │  └──────────────────────────┘  │
│       │ IsServer + IsClient    │         │       │ IsClient               │
│       ↓                        │         │       ↓                        │
│  ┌──────────────────────────┐  │         │  ┌──────────────────────────┐  │
│  │ NetworkCrocodileGame /   │  │  RPC    │  │ NetworkCrocodileGame /   │  │
│  │ NetworkTowerGame         │  │ ◄────►  │  │ NetworkTowerGame         │  │

### Ключевые компоненты

- **`NetworkBootstrap`** *(Assets/Scripts/Network/NetworkBootstrap.cs)* — создаёт `NetworkManager` + `UnityTransport`, управляет старт/стоп подключения, спавнит prefab мини-игры при загрузке сцены.
- **`NetworkPrefabRegistry`** *(там же)* — создаёт сетевые prefab'ы **программно** (в runtime) и регистрирует их через `INetworkPrefabInstanceHandler`. Так удалось обойтись **без редактирования сцен в Unity Editor** — обычно для NGO нужно вручную добавить `NetworkObject` на сцену, и Editor генерирует `GlobalObjectIdHash`. Здесь мы задаём хэш константой через рефлексию, что даёт **одинаковый идентификатор у хоста и клиента**.
- **`NetworkCrocodileGame`** *(там же)* — сетевая логика "Крокодила". Сервер хранит чей ход, какой зуб плохой, какие нажаты. Клиент шлёт `ServerRpc` при клике, сервер валидирует и рассылает `ClientRpc`.
- **`NetworkTowerGame`** *(там же)* — сетевая логика "Башни". Таймер и счёт хранятся как `NetworkVariable`. Каждый игрок управляет своей башней локально, результат сброса блока шлёт серверу через `ServerRpc`.
- **`NetworkLobbyUI`** *(Assets/Scripts/UI/NetworkLobbyUI.cs)* — UI лобби с полями имя/IP/порт и кнопками Host/Join. Сам создаёт `UIDocument` и `PanelSettings` программно. Открывается автоматически при запуске.
- **`LobbyAutoBootstrap`/`NetworkAutoBootstrap`** — `RuntimeInitializeOnLoadMethod`-инициализаторы, создающие всю сетевую инфраструктуру при старте приложения. **Не нужно ничего класть в сцены вручную.**

### Что синхронизируется по сети

| Данные | Способ |
|--------|--------|
| Имена игроков | `NetworkVariable<FixedString64Bytes>` |
| Чей сейчас ход (Крокодил) | `NetworkVariable<int>` |
| Какие зубы нажаты | `ClientRpc` (`PressToothClientRpc`) |
| Укус (анимация + сообщение) | `ClientRpc` (`ShowBiteClientRpc`) |
| Время раунда (Башня) | `NetworkVariable<float>` |
| Число блоков у каждого игрока | `NetworkVariable<int>` |
| Сброс блока игроком | `ServerRpc` (`ReportDropServerRpc`) |
| Конец раунда + результат | `ClientRpc` |
| Загрузка сцены | `NetworkManager.SceneManager.LoadScene` (синхронизированно) |

## Установка проекта

### Требования

- **Unity 6** (6000.0+, проект изначально на Unity 6 — см. `ProjectSettings/ProjectVersion.txt`).
- Никаких сторонних аккаунтов/сервисов не нужно.

### Шаги

1. Открыть проект в Unity Hub (Open → выбрать папку с этим проектом).
2. Unity **автоматически подтянет** новые пакеты из `Packages/manifest.json`:
   - `com.unity.netcode.gameobjects` 2.1.1
   - `com.unity.transport` 2.4.0
3. Дождаться импорта (1–3 минуты). Если Unity спросит про обновление API — нажмите «Yes, for these and other files in the project».
4. Открыть сцену `Assets/Scenes/MainMenu.unity`.
5. **Не нужно ничего добавлять в сцены руками** — `NetworkBootstrap`, `NetworkLobbyUI` и сетевые prefab'ы создаются в runtime автоматически.
6. Убедитесь, что в **File → Build Settings** все 4 сцены добавлены в список (`MainMenu`, `Crocodile`, `TowerBuilder`, `Memory`). Они уже там из оригинального проекта.

### Сборка билдов для запуска на двух устройствах

В **File → Build Settings**:
1. Platform: Windows / Mac / Linux (по вашему OS).
2. Architecture: x86_64.
3. Нажать **Build** и выбрать папку, например `Builds/PartyMiniGames/`.
4. Получится `.exe` (Windows) или `.app` (Mac), который можно перенести на второй ноутбук.

Билд на обоих устройствах **одинаковый** — нет отдельного «серверного» и «клиентского» билда. Кто нажмёт «Host» в лобби, тот и будет сервером.

## Как ИГРАТЬ — пошагово

### Сценарий «два ноутбука в одной Wi-Fi-сети»

**Подготовка:**
1. Скопируйте билд на оба ноутбука.
2. Убедитесь, что оба ноутбука **в одной Wi-Fi сети** (например, в одной комнате через один и тот же роутер).
3. На обоих ноутбуках разрешите Unity-приложению доступ к сети (Windows брандмауэр обычно спросит при первом запуске — нажмите «Разрешить доступ»).

**Узнаём IP хоста:**
- На ноутбуке Игрока 1 (того, кто будет хостом) откройте терминал/PowerShell и выполните `ipconfig` (Windows) / `ifconfig` (Mac/Linux), или просто посмотрите в свойствах подключения.
- Вам нужен IPv4 локальной сети, обычно вида `192.168.x.x` или `10.0.x.x`.
- **Эта же информация показана в самом лобби** — в окне «Сетевая игра» есть строчка «Ваш локальный IP: …». Можно просто посмотреть туда.

**Запуск игры:**

1. **Игрок 1 (Host) — на своём ноутбуке:**
   - Запускает игру.
   - Открывается окно «Сетевая игра».
   - Вводит своё имя, например `Аня`.
   - Видит подсказку: «Ваш локальный IP: 192.168.1.42» — **запоминает или передаёт IP второму игроку**.
   - Нажимает **«Создать игру (Host)»**.
   - Появляется сообщение: «Хост активен на порту 7777. Ждём второго игрока…».

2. **Игрок 2 (Client) — на втором ноутбуке:**
   - Запускает игру.
   - Открывается окно «Сетевая игра».
   - Вводит своё имя, например `Боря`.
   - В поле «IP хоста» вводит IP первого игрока: `192.168.1.42`.
   - Порт оставляет 7777.
   - Нажимает **«Подключиться (Join)»**.
   - Появляется сообщение: «Подключение установлено».

3. **Игрок 1 (Host) видит:**
   - Сообщение в лобби меняется: «Хост активен. Подключено игроков: 2. Можно начинать!».
   - Появляется кнопка **«Закрыть и выбрать игру»** — нажимает её.
   - Главное меню с тремя кнопками. Нажимает «Крокодил» или «Башня».
   - Сцена выбранной мини-игры **загружается на обоих устройствах одновременно** (синхронно через `NetworkManager.SceneManager.LoadScene`).

4. **Игра идёт:**
   - **Крокодил:** в HUD сверху написано «Ход: Аня (ваш ход)» на ноуте Ани и «Ход: Аня (ждём…)» на ноуте Бори. Аня кликает зуб → у обоих зуб нажимается, ход переходит. Боря кликает следующий — и так далее. Кто нажмёт плохой зуб — проигрывает.
   - **Башня:** обе башни видны обоим игрокам. Каждый жмёт пробел на своём ноутбуке, чтобы сбросить свой блок. Таймер 30 секунд. По истечении — экран результатов с числом блоков и победителем (или ничья).

5. **После игры:** автоматически загружается главное меню, показывается экран результатов. Игрок 1 может выбрать следующую мини-игру; игрок 2 ждёт.

### Завершение сессии

- В лобби есть кнопка «Отключиться» — она разрывает соединение.
- Закрытие окна игры одним игроком корректно обрабатывается на другой стороне.

## Как ПРОДЕМОНСТРИРОВАТЬ работу с одного устройства

В реальной демонстрации не всегда есть два ноутбука. Есть три способа показать, что мультиплеер работает, имея только один компьютер:

### Способ 1 (самый простой) — две копии в Unity Editor через ParrelSync / MPPM

**Multiplayer Play Mode (MPPM)** — встроенный в Unity 6 инструмент для запуска нескольких копий редактора. Идеально подходит для демонстрации.

1. Через **Window → Package Manager** установите пакет **Multiplayer Play Mode** (`com.unity.multiplayer.playmode`).
2. Откройте окно **Window → Multiplayer Play Mode**.
3. Включите 2 виртуальных игрока (Player 2).
4. Нажмите Play в основном редакторе — рядом откроется второе окно с независимой копией игры.
5. В первом окне нажмите «Host», во втором введите IP `127.0.0.1` и нажмите «Join».
6. Играйте: видно, что нажатие зуба на одном окне отражается на другом, ход переключается синхронно.

### Способ 2 — два standalone-билда на одном компьютере

1. Соберите Standalone-билд (Build And Run).
2. Запустите билд **дважды** (два экземпляра .exe одновременно).
3. В первом нажмите «Host». Во втором введите IP `127.0.0.1` (или `localhost`) и нажмите «Join».
4. Играйте, видны оба окна одновременно.

> ⚠️ На Windows второй экземпляр иногда не запускается, если первый «захватил» exclusive-режим. Тогда используйте Способ 1 или Способ 3.

### Способ 3 — Unity Editor + standalone build

1. Соберите Standalone-билд один раз.
2. Запустите Unity Editor с открытым проектом, нажмите Play (роль Host, нажмите «Host»).
3. Запустите standalone-билд (роль Client, IP `127.0.0.1`, «Join»).
4. Играйте, переключаясь между окнами.

### Что нужно показывать при демонстрации

Чтобы проверяющий увидел, что это действительно мультиплеер на двух машинах, а не один экран:

1. **Запуск двух независимых окон** игры (любым из способов выше).
2. В одном окне нажать «Host», во втором ввести **IP** — видно, что IP передаётся как сетевой параметр (можно даже спросить второй компьютер по `ipconfig`).
3. Открыть мини-игру «Крокодил»:
   - В окне Игрока 1 нажмите зуб — **на втором окне зуб тоже нажимается без участия пользователя** (это RPC).
   - В первом окне в HUD пишет «(ваш ход)», во втором — «(ждём…)» — значит, состояние различается, но синхронизировано.
   - После клика на одном окне состояние меняется: теперь во втором «(ваш ход)», в первом «(ждём…)».
   - Если попытаться кликнуть зуб не в свой ход — игра покажет «Не ваш ход» и не отправит запрос серверу.
4. Открыть «Башня»:
   - Каждый игрок жмёт пробел в своём окне — блок падает в своей башне.
   - Таймер идёт синхронно в обоих окнах.
   - По окончании отображается победитель/ничья **на обоих окнах одновременно**.
5. В консоли Unity (Console window) можно увидеть логи `[NetworkBootstrap] Host запущен на порту 7777`, `[NetworkBootstrap] Клиент подключается к 127.0.0.1:7777`, `[Netcode] Synchronizing scene 'Crocodile'…` — это подтверждает, что используется реальный сетевой стек NGO.

## Известные ограничения

1. **Memory в сетевой версии не реализован.** В главном меню кнопка Memory доступна **только в локальном режиме** (если ни один игрок не нажимал Host/Join). Для демонстрации мультиплеера используйте «Крокодил» и «Башня».
2. **Подключение только через прямой IP.** Без NAT-traversal — игроки должны быть в одной локальной сети. Для игры через интернет понадобился бы Unity Relay (но это вне рамок учебного проекта).
3. **Подключение только к одному порту.** По умолчанию 7777. Можно поменять в полях лобби, главное чтобы у обоих игроков значение было одинаковое.
4. **Программная регистрация prefab'ов через рефлексию.** В `NetworkPrefabRegistry.ForceSetGlobalObjectIdHash` используется рефлексия для записи в `internal uint GlobalObjectIdHash` поле NGO. Это работает в NGO 2.1.1 и выше. Если Unity когда-нибудь переименует поле — нужно будет обновить код (это единственное место, чувствительное к версии NGO).

## FAQ

**Q: Почему «Игрок 1» — всегда хост?**
A: В лобби тот, кто нажимает «Создать игру (Host)», становится Player 0 (Игрок 1). Тот, кто нажимает «Подключиться (Join)», становится Player 1 (Игрок 2). Цвета: Player 1 — красный, Player 2 — зелёно-голубой (как в оригинальном проекте).

**Q: Что если у обоих игроков один и тот же IP?**
A: Если оба запустили на одном компьютере (например, для тестов) — используйте `127.0.0.1` или `localhost` в поле IP при подключении. Это loopback-адрес, означающий «тот же компьютер».

**Q: Игра «зависает» при подключении.**
A: Скорее всего, проблема в брандмауэре Windows/Mac. На стороне хоста разрешите Unity / вашему .exe доступ к сети. Также проверьте, что порт 7777 не занят другим приложением.

**Q: Можно ли запустить игру через интернет (разные города)?**
A: По умолчанию — нет, потому что у пользователей в интернете нет публичного IP. Для этого нужен Unity Relay или проброс портов на роутере. Если очень хочется протестировать через интернет — используйте, например, `Hamachi` или `Radmin VPN`, которые создают виртуальную локальную сеть между двумя компьютерами.
